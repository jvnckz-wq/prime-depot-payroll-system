# Prime Depot Payroll System

A web-based payroll and attendance system for Prime Depot Hardware and Construction Supply in Mabini, Batangas. It handles two kinds of pay in one place: office staff on a monthly salary with government deductions, and truck crew who are paid per delivery (pakyawan). Attendance comes from a biometric device, so the payroll is based on real time records.

Live site: https://prime-depot-payroll-system.vercel.app

## What it does

The system replaces the old manual, spreadsheet-based payroll. In short, it lets the Operations Head:

- Import attendance from the biometric device, review each person's Daily Time Record, and track leave credits.
- Compute office staff salaries with SSS, PhilHealth, Pag-IBIG, and withholding tax, then print payslips.
- Log truck deliveries, apply the piece rates (with an optional double rate for far or hard routes), and compute each crew member's pay.
- Keep employee records for both staff and crew, deactivate a person who leaves, and produce a final pay slip.
- Record loans and apply the deductions to payroll.
- Finalize a cutoff so the records for that period become the official copy, and look back on past cutoffs.
- Export data and view simple reports.

## Who uses it

- Operations Head (admin): full access to everything above. There is only one admin account.
- Checker: can log deliveries only. Checker accounts are created by the admin.

Accounts are never deleted, only deactivated, so the delivery and payroll history stays complete.

## Security

- Password login with a forced password change on first sign in.
- Two-factor authentication (authenticator app plus backup codes) for the admin.
- Password reset by verified email.
- Sensitive actions are written to an audit log.

## Tech stack

- Next.js (App Router) and React for the app.
- Tailwind CSS for styling.
- Prisma with a Neon PostgreSQL database.
- Deployed on Vercel.
- Supporting libraries: recharts (charts), xlsx (Excel import and export), node-zklib (biometric device), nodemailer (email), otplib and qrcode (two-factor).

The code is JavaScript. A few helper scripts under the project use TypeScript.

## Project structure

The code is organized by layer, so a folder's name tells you what kind of code is inside.

### Frontend

`src/app/page.js`, `src/app/layout.js`, `src/app/globals.css`, `src/shell`, `src/features/<feature>`, `src/components`, `src/data`

The screens people use: this code runs in the browser, never touches the database, and gets all of its data by calling `/api/...`.

### Backend: API routes

`src/app/api/**`

The folder path is the URL and the exported function name (`GET`, `POST`, `PATCH`, `DELETE`) is the action; every route checks the caller's role first, except the sync agent's routes, which check the device sync token, and the sign-in and password-reset steps under `/api/auth`, which have to work before anyone is signed in.

### Backend: services

`src/lib/server/services`

The business logic the routes call, computed from the database: shaping records, loan deductions, payroll inputs, and the attendance import.

### Shared business rules

`src/lib/payroll.js`, `src/lib/loan-rules.js`, `src/lib/attendance.js`

The same functions run in the browser for previews and on the server for the real result, and the server always recomputes from the database instead of trusting numbers sent by the browser. `src/lib/utils.js` holds browser-only helpers such as peso formatting and Excel export.

### Authentication and security

`src/lib/server/security`, `src/app/api/auth/**`, `src/shell/IdleTimeout.jsx`, security headers in `next.config.mjs`

Passwords are stored as bcrypt hashes and each session is a random token in an httpOnly cookie with only its hash saved in the database, backed by login throttling, TOTP two-factor with hashed backup codes, the ADMIN and CHECKER roles, idle logout, upload size limits, the device sync token, and the audit log.

### Database

`prisma/schema.prisma`, `prisma/migrations`, `src/lib/server/db`, `src/generated/prisma`

Neon Postgres, accessed through Prisma; `src/generated/prisma` is generated by Prisma and must never be edited by hand.

### Integrations and external services

`src/lib/server/integrations`, `scripts/sync-agent.js`, `scripts/pull-cutoff.js`

The outside services the system depends on: Gmail for email, an authenticator app for two-factor codes, the ZKTeco biometric device through the sync agent on the warehouse laptop, Vercel for hosting, and Neon for the database.

### Tooling

`package.json`, the config files (`next.config.mjs`, `eslint.config.mjs`, `postcss.config.mjs`, `jsconfig.json`, `prisma.config.ts`), `tests/`, `scripts/admin/`

The tools that build, check, and test the app, plus the admin maintenance scripts.

Secrets live in `.env.local`, which is never committed or shown.
